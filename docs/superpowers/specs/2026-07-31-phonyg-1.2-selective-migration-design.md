# PhonyG 1.2 Selective Migration Design

## Release

Update Docker release metadata and documentation from 1.1 to 1.2, commit locally, create annotated tag `v1.2`, and push `main` plus the tag. Poll the matching GitHub Actions builds once per minute. Pull `ghcr.io/buukow/phonyg:1.2` through `ghcr.nju.edu.cn`, and require the accelerated image digest to match the source GHCR digest.

## Backup and Fresh Deployment

Only host port 23346 may be published. Stop the existing `phonyc` container, preserve its full inspect output and image digest, and move `/root/phonyc-deploy/data` as a whole to a timestamped backup directory. Never delete that backup automatically.

Create an empty `/root/phonyg-deploy/data`, start container `phonyg` with `PHONYG_ADDR`, `PHONYG_DATA_DIR`, the existing timezone, restart policy, and only `23346:8080`. Verify the fresh 1.2 process and health endpoint, then stop it for migration.

## Selective Data Migration

Use Python's SQLite backup API against the stopped legacy database so its WAL content is included in a consistent temporary snapshot. From that snapshot, migrate only:

- `channels`
- `channel_models`
- `user_keys`

Do not migrate administrators, client presets, settings, request logs, statistics, capture data, or any other application records.

Preserve primary keys and channel-model foreign keys. For every migrated user Key, clear `preset_id`. If `impersonation_mode` is `preset`, change it to `passthrough`; other modes and custom headers remain unchanged. The new database schema is created by PhonyG 1.2 before rows are inserted.

## Verification and Rollback

Before migration, count legacy channels, channel models, and user keys from the consistent snapshot. After migration, require exact matching counts, require no dangling channel-model references, require every Key `preset_id` to be null, and require no Key to retain preset mode.

Start PhonyG and require it to remain running for 15 seconds. `http://127.0.0.1:23346/api/health` must return HTTP 200 with `{"status":"ok"}` within five attempts. Verify the three migrated table counts again from the live database and confirm non-selected application tables contain only fresh defaults/seed data.

On any failure, stop and retain the failed PhonyG container/data, restore the moved legacy directory to its original path, and restart the prior `phonyc` image/configuration on port 23346.
