# 文档导航展开状态与星标显示修复设计

## 目标

修复 Just the Docs 侧栏的两个显示问题：多个一级菜单可以同时保持展开，并且“客户端预设 ⭐”“请求捕获 ⭐”“自动测活与增强模式 ⭐”中的星标在普通、激活和跨页面状态下始终作为标题文本正常显示。

## 导航状态

- 保留主题原有的独立展开按钮和 `active` 状态机制。
- 使用浏览器 `localStorage` 记录每个带子菜单节点的展开状态，节点以父页面链接路径作为稳定标识。
- 页面加载后恢复所有手动展开的菜单，不关闭其他菜单。
- 当前页面所属菜单仍由主题自动展开，并与已保存的其他展开菜单合并。
- 用户收起某个菜单时，只更新该菜单，不影响其他菜单。
- 自定义点击监听器在主题点击处理器完成后通过下一事件循环读取最终状态，避免保存切换前的 `active` 值；恢复时同时设置父节点 `active` 和按钮 `aria-expanded`。
- 恢复逻辑在 DOM 就绪后延迟到主题 `activateNav()` 完成之后执行，避免被主题初始化覆盖。

## 星标显示

- 星标继续保存在页面 Front Matter 的 `title` 中，仍属于原始文本，不通过 JavaScript 或伪元素重新生成。
- 为侧栏链接补充彩色 Emoji 字体优先回退和 `font-variant-emoji`，避免不同操作系统或普通/粗体字重下无法为 `⭐` 选择可用字形。
- 不改变三个页面的标题、永久链接和导航顺序。

## 集成方式

- 新增导航状态脚本，并通过 `head_custom.html` 在所有文档页面加载。
- 在现有自定义 SCSS 中增加侧栏 Emoji 字体规则。
- 扩展文档结构校验，确认脚本、加载入口、样式规则和三个星标标题持续存在。
- 新增 Playwright 回归脚本，以 `DOCS_BASE_URL`（默认 `http://127.0.0.1:23342/PhonyC/`）为入口，使用父页面链接路径和 `.nav-list-expander` 作为稳定选择器。
- 回归断言至少包括：两个以上一级 `.nav-list-item.active` 同时存在；`localStorage` 中的展开状态跨页面保留；收起一个菜单不会收起另一个；三个链接的 `textContent` 均含 `⭐`、链接和星标字符布局宽度大于 0，并且计算字体包含 Emoji 回退字体。
