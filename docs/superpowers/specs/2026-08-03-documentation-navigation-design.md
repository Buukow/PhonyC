# 文档导航与快速开始重组设计

## 目标

重组 GitHub Pages 文档的信息架构，使“快速开始”成为一级父菜单，并将构建、部署和首次使用流程拆成三个清晰的二级页面；同时精简 Docker 部署页，并在功能指南导航中突出三个核心能力。

## 导航结构

- 首页
- 快速开始
  - 本地构建
  - Docker 部署
  - 如何使用
- 功能指南
  - 概览与统计
  - 渠道与模型映射
  - 用户 Key 与伪装模式
  - 客户端预设 ⭐
  - 请求捕获 ⭐
  - 请求日志
  - 自动测活与增强模式 ⭐
  - 自动重试
- 配置参考

“快速开始”使用 Just the Docs 的 `has_children: true`。三个子页面使用 `parent: 快速开始`，并按本地构建、Docker 部署、如何使用的顺序排列。既有页面的永久链接保持不变；新增“如何使用”页面使用 `/how-to-use/`。

## 页面调整

### 快速开始

父页面不再承载完整操作步骤，仅说明三个子页面的用途并提供入口：

1. 本地构建：开发、调试和源码构建。
2. Docker 部署：镜像、Compose 和容器环境变量。
3. 如何使用：管理员初始化到首次 API 请求。

### 本地构建

正文和永久链接保持原样，仅调整 Front Matter，使其成为“快速开始”的第一个子页面。

### Docker 部署

正文和永久链接总体保持原样，并进行以下定向调整：

- 成为“快速开始”的第二个子页面；
- 保留当前完整 Docker Compose 示例；
- 在完整示例旁增加仅含镜像、重启策略、端口和数据卷的最简 Docker Compose；
- 删除“检查状态与日志”“升级”“备份与回滚”三个章节；
- 保留使用预构建镜像、环境变量和自行构建镜像等内容。

### 如何使用

新增为“快速开始”的第三个子页面。把原快速开始页从“初始化管理员”开始的使用流程迁移到此页面，并重新编号：

1. 初始化管理员；
2. 创建上游渠道；
3. 创建用户 Key；
4. 发出请求。

保留 OpenAI Chat Completions、OpenAI Responses 和 Anthropic Messages 三类请求示例，以及模型映射提示。

### 功能指南重点项

“客户端预设”“请求捕获”“自动测活与增强模式”的页面标题和一级正文标题都追加黄色星星字符 `⭐`，使导航与页面标题一致。永久链接和排序不变。

## 校验与发布

更新 `scripts/check-docs.mjs`，验证：

- 快速开始具备子页面声明；
- 三个子页面的父级、顺序和永久链接正确；
- “如何使用”包含四步使用流程；
- Docker 页同时包含完整与最简 Compose，且不再包含三个删除章节；
- 三个重点功能页包含星标标题。

完成后运行文档校验、Jekyll 构建和 `git diff --check`，再检查 23342 实时预览中的导航与关键页面。验证通过后提交并推送 `main`，等待 GitHub Actions 和 GitHub Pages 发布完成，并确认正式文档地址可访问。
